Anatomy -- annotated YAML

documentation / readme hero

A single labelled block where every field is numbered, and the right rail explains each one. Default behaviour: stages run in parallel. Use needs for sequencing.

koto.yaml
# -- HEADER -----------------------------------------
version: "1"                       # 1 schema version
name:    blog-pipeline             # 2 project name

# -- AGENTS -----------------------------------------
agents:                                # 3 the ensemble
  - id:      researcher              # 4 unique handle
    role:    "Research latest AI news"
    model:   claude-sonnet-4-5       # 5 default
    context: ["sources/**/*.md"]     # 6 file globs

  - id:   writer
    role: "Draft blog post"
  - id:   editor
    role: "Copy-edit & fact-check"
  - id:   seo
    role: "Optimise headline & meta"

# -- FLOW -------------------------------------------
flow:                                  # 7 orchestration
  stages:                              # 8 default: parallel
    - id: research
      agent: researcher
      output: research.md              # 9 artifact out

    - id: draft                       # 10 runs parallel to seo
      agent: writer
      needs: [research]                # 11 waits for research
      input:  research.md              # 12 artifact in
      output: draft.md

    - id: seo-check                   # 10 runs parallel to draft
      agent: seo
      needs: [research]

    - id: edit
      agent: editor
      needs: [draft, seo-check]        # 13 waits for both
      input:  draft.md
      output: final.md

# -- STATE ------------------------------------------
state:                                 # 14 defaults to local
  backend: local
  path:    .koto/state
1version -- locks the schema. Always "1" today. Required so breaking changes can ship later.
2name -- human-readable project id. Shows up in koto ls and state file.
3agents -- list of the players in the ensemble. At least one.
4id -- unique handle used in flow stages. snake_case recommended.
5model -- picks an LLM. Defaults to claude-sonnet-4-5.
6context -- file globs mounted read-only for the agent.
7flow -- how agents are orchestrated. Absent = all agents run once in parallel.
8stages -- list of work units. Default: all run in parallel. Use needs for ordering.
9output -- file this stage writes to the shared workspace.
10Stages without mutual needs run concurrently -- draft and seo-check start at the same time.
11needs -- declares which stages must finish first. The only sequencing mechanism.
12input -- file(s) mounted for this stage. Declares the data dependency.
13Multiple needs = wait for all. edit starts only after both draft and seo-check finish.
14state -- where run state lives. local (default) or remote s3/gcs/http.

Hero -- minimal & full, side by side

readme top-fold

The "zero-to-sixty" pitch. 4-line hello-world on the left; the full multi-agent flow on the right.

minimal

4 lines. one agent. no flow needed.
version: "1"
name:    hello
agents:
  - { id: bot, role: "say hi" }
$ koto up -> runs bot once, prints output

full

4 agents / 4 stages / parallel by default / needs for sequencing
version: "1"
name:    blog-pipeline

agents:
  - { id: researcher,  role: "Research latest AI news",
      context: ["sources/**/*.md"] }
  - { id: writer,      role: "Draft blog post" }
  - { id: illustrator, role: "Generate hero images",
      model: claude-opus-4-5 }
  - { id: editor,      role: "Copy-edit & fact-check" }

flow:
  stages:
    - id: research
      agent: researcher
      output: research.md

    - id: draft
      agent: writer
      needs: [research]
      input: research.md
      output: draft.md

    - id: images
      agent: illustrator
      needs: [research]
      input: research.md
      output: img/*.png

    - id: edit
      agent: editor
      needs: [draft, images]
      input:  [draft.md, img/*.png]
      output: final.md

state:
  backend: local
  path:    .koto/state
$ koto up -> research -> (draft | images) -> edit
