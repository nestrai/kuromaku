## Architectural Insights

Beyond individual component optimizations, three structural patterns emerged that warrant new issues:

### 1. Flow Consolidation: fix-issue and development Overlap

Both `fix-issue` and `development` flows implement similar patterns:
- Design phase (Neo for architectural decisions)
- Implementation phase (Minion for coding)
- Verification (review/test)

**Proposal**: A single `implement-issue` flow that handles any issue type (fetch → design → test-plan → implement → review → ship) could replace both, reducing maintenance burden and cognitive load for users.

**Status**: Architecture tracked in #49. Audit should have flagged the duplication.

**New issue**: #73a - Consolidate fix-issue and development flows into implement-issue

### 2. Missing CLI UX Evaluation

The audit evaluated prompts and rules through an AI engineering lens but ignored user interaction. Key gaps:

- Which flows does a user need? 
- How do they choose between fix-issue and development?
- Is the naming intuitive?
- What's the mental model for sequencing flows?

**Proposal**: Conduct a separate UX audit evaluating user workflows, naming clarity, flow discoverability, and onboarding friction.

**New issue**: #73b - UX audit of flow selection and naming

### 3. Preventive Test Planning Pattern

Learning from previous implementations: review findings about missing tests and scope creep are better prevented upstream than caught downstream. Optimal pattern:

1. Design (one agent)
2. **Test Plan** (different agent) ← critical checkpoint
3. Implement (different agent)
4. Review (final quality gate)

Current flows skip step 2, pushing quality concerns to the final review. This is inefficient and creates rework loops.

**Proposal**: Add test-plan step to implement-issue flow (and migration path for existing flows).

**Status**: Conceptually validated but needs formalization. #67 (validation steps) partially covers this but doesn't emphasize test planning as a separate design-time phase.

**New issue**: #73c - Add test-plan step to flows implementing new code

## Conclusion

The .koto/ content demonstrates solid AI engineering fundamentals at the component level. Beyond individual optimizations, the audit identified three strategic architectural opportunities:

**Component-level improvements** (optimization & refinement):
- **Prompt engineering**: Missing few-shot examples and explicit output formats (standard gap in initial implementations)
- **Flow design**: Lack of validation/reflection steps increases compound error risk
- **Rule composition**: Good structure, would benefit from concrete examples

**Architectural improvements** (strategic):
- **Flow consolidation**: fix-issue and development overlap; implement-issue would unify the pattern
- **UX clarity**: User interaction model and flow discoverability not evaluated
- **Quality prevention**: Test-plan as a separate phase prevents rework loops

**Implementation strategy**:
Phase 1 addresses architecture (3 issues, high impact).
Phase 2 tackles prompt engineering (3 issues, high impact).
Phases 3-4 handle polish and cleanup.

No breaking issues found. All agents and flows are functional and follow core principles. The improvements will enhance both reliability/output quality and user experience.
